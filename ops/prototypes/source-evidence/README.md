# Disposable source-evidence SQL prototype

**NOT A MIGRATION. Never apply schema.sql to a hosted database or expose evidence_probe.** The standalone script creates a new in-memory PGlite instance, uses synthetic owners/policies/claims and closes it in finally. It has no URL, credentials or hosted-database option. No app dependency is added.

Run with an externally installed pinned PGlite package (tested 0.5.13):

```sh
PGLITE_MODULE_URL=file:///absolute/scratch/tooling/node_modules/@electric-sql/pglite/dist/index.js node scripts/source-evidence-db-check.js
```

The prototype stages canonical package/manifest bytes, per-case JSON projections, actor-scoped request receipts and events in one SQL function transaction. SQL verifies manifest and receipt-payload byte hashes and binding consistency. Existing JavaScript strict/JCS preparation is mandatory before this trusted server-only call; The supplemental digests.sql now independently derives case/appearance/manifest/request/receipt hashes for the restricted metadata domain and checks canonical supplied bytes. The script independently rehashes stored claims and resolves a selected mixed-source case after a separate readback. SQL returns **committed**, never accepted; this is not the final staging adapter.

Checks exercise exact receipt retry; changed request/same revision conflict; exact older revision read after a new version; wrong version/digest/actor denial, including a second enabled owner attempting existing revisions, retries and new versions; rollback after revision, cases, request and event insertion; immutable-record write privileges; anon/authenticated direct table/function denial; missing owner authority; manifest/receipt byte tampering and recomputed approval-flag rejection; selected second-source rights denial on full-package operations; authority denial on retry/readback. The first positive check was observed failing against a function returning an empty result before implementation. The validation increment separately observed acceptance of a rehashed malformed receipt before the shape fix, then rejection afterward; missing history writers were observed before implementation.

The private schema revokes browser usage and function EXECUTE, enables RLS, and grants backend SELECT/INSERT only for immutable evidence records. Authority/source-policy fixtures are seeded/changed by the disposable administrator, never by the backend role. SECURITY INVOKER functions have empty search_path. Actor arguments are synthetic delegated server identities; this does not authenticate sessions or prove real account membership. Backend credentials remain trusted; unrelated browser users cannot call these RPCs.

This remains a disposable prototype of SOURCE_EVIDENCE_DATABASE_DESIGN.md. It now has an immutable package owner/lexical-ID row, revisions/cases/requests/events, and append-only versioned authority/source-policy history. Its private administrative writers use the same advisory transaction lock as staging/readback. Current checks select the latest history version, so an older allow cannot bypass a later deny. Backend/browser roles cannot invoke the authority writers; the disposable administrator seeds/transitions synthetic state. These are fixture governance roles, not real owner/session verification. No reviewer grants, withdrawal/erasure lifecycle, byte retention or export/restore is implemented.

SQL independently validates exact package/case/appearance/interpretation shapes and scalar limits, distinct case IDs, binding fields, receipt keys/UUIDs/canonical millisecond UTC date strings and false approval flags. The same receipt invariants apply to staging, stored readback and exact retries. Readback binds canonical documents to actual package/revision/request rows and reconciles per-case projections; raw-inserted inconsistent records are rejected. Negative tests include rehashed malformed receipts, forged claims/manifests/request fingerprints, corrupted case projections and mismatched physical package keys.

`digests.sql` implements domain_canonical/domain_hash only for ASCII printable strings/keys and integers 0..1e9, plus boolean/null/array/object structure. It explicitly rejects Unicode/control strings, negative/fractional/out-of-range numbers. It is **not a general RFC8785 serializer**. Valid evidence labels/locators, UUIDs, timestamps, hashes and profile literals fit this restricted domain. ASCII C-order key sorting and integer serialization are compared to the existing JavaScript canonicalizer. Twelve oracle packages exercise all six relations, four rotations, null/proposed identity, mixed sources and integer boundaries. Helper serializer quoting/backslash and numeric-scale cases also match JavaScript; unsupported-domain cases reject.

SQL independently constructs appearance/case hashes, sorted package manifest/profile, sorted claimsDigest, request fingerprint and receipt checksum. Canonical byte comparison rejects whitespace, reordered object keys or duplicate-key spellings rather than silently hashing JSONB::text. Case-array order is normalized only for stored package snapshots/digests, allowing a reversed-order exact retry to return the original receipt. Stage requires schema validation before digest derivation; readback recomputes from stored canonical documents. Existing JavaScript validation remains mandatory at the eventual adapter boundary. This is tested restricted-domain parity, not general JCS certification or exhaustive cross-engine equivalence.

The private writers serialize inside the embedded instance; no real multi-connection race, hostile Auth session, network/crash durability, postcommit uncertainty mapping, corrupted-store readback, reusable transaction-driver conformance or complete export/restore acceptance has been demonstrated. Existing production authority writers are unrelated to these fixture functions and have not been integrated. A new allowed policy event is an explicit administrative fixture transition, not automatic access restoration by retry. History cannot be updated/deleted, even by the disposable administrator through ordinary SQL; the admin remains trusted for new append events and platform DDL.

Fault injection is intentionally callable only in this disposable fixture and must never enter a production API. SQL returns committed, not accepted. No hosted migration, real grant/source upload, production RLS/Auth assurance or learner publication follows.

The disposable driver below now runs the existing transaction conformance harness against SQL records. Keep hosted migrations/API wiring/reviewer grants/source bytes disabled until remaining authorization, concurrency and recovery requirements pass.

Primary references consulted for this increment: [RFC8785](https://www.rfc-editor.org/rfc/rfc8785) and [PostgreSQL JSON functions](https://www.postgresql.org/docs/current/functions-json.html). No new SQL extension/service is introduced.

## SQL transaction conformance driver

Run the reusable transaction harness against real disposable SQL tables/functions:

```sh
PGLITE_MODULE_URL=file:///absolute/scratch/tooling/node_modules/@electric-sql/pglite/dist/index.js node scripts/source-evidence-sql-conformance.js
```

`scripts/lib/source-evidence-sql-driver.js` creates/closes a fresh in-memory database per scenario. It captures and validates the candidate before asynchronous work, recomputes the canonical envelope, stages through SQL and returns accepted only after a separate protected SQL readback plus independent JavaScript package/receipt checks. `inspect()` queries committed revisions, requests and events; it does not keep a parallel success-state mirror. The harness independently rehashes inspected claims and checks request/receipt bindings. Inspection projects the fixed lower-case UUID fixtures used by this harness; it is not a generic export or client endpoint.

The driver passes all ten existing scenarios: exact retry, request/revision conflicts, atomic precommit failure, lost acknowledgement, unavailable/tampered readback, overlapping identical/conflicting calls and authority recheck. Three deliberately broken wrappers must be rejected: accepting uncertain outcomes, accepting corrupted readback and reporting inconsistent stored claims. Each wrapper closes its database through the harness finally block.

Fault distinctions matter: before-commit injects an actual SQL exception after case insertion and verifies no committed revision/request/event; the standalone SQL probe separately checks four write-boundary rollbacks, including package records. After-commit and readback-unavailable simulate failed delivery after a successful SQL statement, rather than killing a server or demonstrating a real network outage. Readback-tampered alters the returned candidate projection, not the stored SQL records; retry reads unchanged records. These deterministic faults prove driver's fail-closed status/receipt handling, not crash durability.

A promise queue serializes this driver's single embedded connection, including the privileged fixture deny writer. Overlapping Promise.all calls therefore test request convergence through this driver, not independent PostgreSQL connection locking or a production revoke race. No hosted Auth session, production authority path, export/restore, deployed adapter, source bytes or reviewer grant is added. Unknown SQL outcomes return uncertain; integrity/denial results expose no receipt. Malformed pre-SQL candidates return invalid without writes. The fixture administrative role never escapes through its public driver surface; it only seeds fixed synthetic authority/policy and appends the test deny event.

Next: extend reusable acceptance coverage for metadata withdrawal and postcommit current-access denial, then consistent disposable export/restore and true multi-connection acceptance before hosted adapter/API consideration. These are still private prototypes, not production migration candidates.

Lifecycle regression checks start staging and immediately close the driver, including two concurrent close callers. Preparation/hashing, SQL and readback all belong to the tracked queue; close waits for the entire in-flight operation, and repeated close calls share its completion. New staging after close rejects. These paths were observed failing before their fixes.
