Current direction — 8 October 2026. The owner cancelled the fixed respiratory batch; the former 12-question/three-note plan is superseded. This is an intake plan, not supplied clinical inventory, approval or an import receipt.

## Scope

Receive the owner's final polished PYQs without a fixed minimum count, required disease set or note count. Preserve the actual questions and tasks. Link useful canonical notes where warranted; do not create respiratory placeholders or manufacture missing patterns. Erased pilots, seed catalogs, pre-reset backups and engineering fixtures remain excluded from clinical reimport.

## Required evidence

- Archive unchanged supplied files with filenames, accessible-byte SHA-256, extraction coverage and exact locators. Preserve available upstream originals separately from polished derivatives; missing upstream originals remain an explicit provenance gap.
- Retain exact supplied stems, all option labels/order/text, images, historical keys, current-key evidence and explanations. Never infer equivalence or approval from “polished.”
- Record actual exam/year/session/recall lineage and source/creator/edition/page/URL evidence, plus reuse rights for text and assets. User declarations remain declarations until evidenced.
- Preserve one canonical concept and question identity, with separate source appearances and exam occurrences. PYQ display precedence supersedes platform banks; non-PYQ priority remains Marrow → PrepLadder → DAMS. Conflicting keys/concepts and uncertain near matches stay in review.
- Preserve actual classification.tasks and optional schema-v2 task/qualifier/presentation/reasoning metadata. No imagined exam frequencies, years, task coverage or holdout status.

## Handoff and review

1. Extract and validate the actual supported records; use current schema-v1/v2 app fields and limits. Split larger batches deterministically (maximum 100 questions per import plus the other payload/record limits).
2. Save reusable Markdown, applicable JSONL, source/occurrence/asset references, checksums, validation and changes in an immutable Drive release; verify saved bytes/receipts. PR #204 supplies converter/orchestration code, not configured live external ports or a watcher.
3. Stage supported text through authenticated admin or the existing connected repository content/inbox workflow. Observe the actual draft and readback; saving or committing files alone is not ingestion/publication.
4. A genuine authorized administrator inspects the exact target and source-rights evidence, then uses Review & publish. No agent supplies a fabricated human attestation.
5. Verify published Notes/Graph counts, source/keyword filters, Study scoring/reload and source links on phone/tablet/desktop; native iOS acceptance remains separate. Actual learner observations must come from genuine activity.
6. Identical retries reuse receipts; changed payloads need new import IDs. Images/corrections/unsupported response formats use their verified routes and must not be stripped to fit text intake.

Ordinary PYQ intake needs no shortening pilot, unseen holdouts or research enrollment. Optional derivatives retain the eight review checks and exact original-version binding; any later experiment has independent consent, allocation, exposure and outcome gates. Private question-only imports remain deferred.
