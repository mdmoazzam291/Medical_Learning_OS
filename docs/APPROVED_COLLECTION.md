# Approved Collection — current evidence preflight

Implements the first read-only portion of slice 3 in the owner-approved Coverage Index design (#331). It is based on PR332, independently of the later concept/syllabus write stack, and does not implement the proposed per-item publication cutover (#330).

Master Admin → Content & Quality → Approved Collection lists exact question and note versions, lifecycle, medical/reference/rights fingerprint states, source-rights receipt validity and unresolved/correction-required learner issue counts. Counts distinguish versions from canonical identities. A newer draft cannot hide an older stored-published version. Search/type/evidence filters and pagination use server allowlists; reload and browser history preserve choices. Each request is a new observation, with its own timestamp and catalog version; pagination is not a frozen release selection.

“Current review evidence” means the three existing gate fingerprints match immutable approved receipts, source identities/counts resolve, rights are currently allowed with matching source fingerprints, lifecycle is verified/published, and no open exact-version reports are present. It is not a new clinical approval, official-syllabus approval or permission to release. External discrepancies such as #326 remain outside this observation. Release readiness is always not-assessed and publicationAuthority=false. Stored published is the old lifecycle flag, not a verified new distribution receipt or a claim that an individual learner can access it. No green publish badge or mutation control is added.

The service-only RPC is STABLE/SECURITY INVOKER with an empty search_path, validates the singleton Admin, and reads existing canonical/review/source/report tables. It creates no table and writes no row. At most 2,000 total versions and an 8 MB source/output bound are accepted; oversized or malformed sources fail rather than truncate. The existing Owner API Auth/runtime/session/Admin gates precede it. The browser cannot supply its own actor and anon/authenticated cannot execute it directly. Only version/identity/state/count metadata leaves SQL; no stems, answers, note bodies, source evidence, reviewer identities/notes or learner reports are projected.

Source-only migration: 20261029094149_admin_approved_collection_preflight.sql, generated with the Supabase CLI. Deploy the migration and a complete compatible Owner API bundle before the frontend. Missing backend renders Collection unavailable. Never call the batch Review & publish function from this control. Existing learner delivery, approvals, attempts and catalog content remain untouched. Rollback removes the UI/route; the RPC has no stored collection to migrate or restore.

## Verification and limits

Domain/API/view regressions, isolated PostgreSQL fixture access/redaction/current/stale/missing/rights/report scenarios and full repository tests are run during implementation. SQL fixtures stub the established fingerprint functions; they do not independently verify every production fingerprint implementation. Native Chromium/WebKit synthetic scenarios are registered in Foundation CI. Local browser launch failed because the runtime browser is absent; its download failed. No local browser pass, real account acceptance, production-scale latency, full migration-chain replay, hosted migration, deployment, content approval or publication is claimed.

The next extension is governed exact-version approved selection and per-item distribution, after resolving #330's authorization/cutover boundaries and #326's source/review discrepancies. Standalone note authoring and accepted syllabus activation remain separate unfinished slice-2 work. This increment alone does not complete the overall proposal.
