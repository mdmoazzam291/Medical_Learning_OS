# Offline owner delegation design

Continue the authorized owner-adapter proposal without enabling a route. Caller input must not supply actor/session, verified flags, role, feature state or arbitrary SQL. A private server closure accepts trusted `verifyUser(token)` and a narrow gateway `query(sql,values)` connection. The verifier must perform authentic server verification for that exact token (future existing getUser adapter); its callback is a trust boundary, not a signature implementation. Only a verified ID plus that token's valid matching sub/session claims may reach the gated SQL wrappers. Capture input synchronously before the verifier's first await and verify again after commit before readback/delivery. No shared mutable identity state.

Approaches: a serializable verified-context object is forgeable by callers; adding database JWT verification requires new key/issuer management and is out of scope. Use a private closure with fixed prepared stage/readback statements and no caller authority fields. This is the implementer's choice within the existing authorized prototype scope, not a new production architecture approval.

The test-only `scripts/lib/source-evidence-owner-delegation.js` factory exposes `stage({accessToken,candidate})` and `readback({accessToken,target})`. Candidate is the existing exact staging contract. Target has packageId/packageVersion/packageDigest/requestId, no latest fallback. Return only bounded status and verified original receipt; no raw SQL/Auth errors or credentials. Stage returns accepted only after committed result, repeat verification and separately gated canonical package/manifest/receipt readback. Readback returns available after equivalent exact binding verification. Unknown commit or unavailable readback remains uncertain. Invalid authority denies. Existing current SQL checks enforce feature/session/account/Admin/owner/source/withdrawal; no metadata checksum establishes rights or token authenticity.

Non-goals: production files/routes/migrations/credentials, actual cryptographic verifier, HTTP origin/streaming body/cache controls, provider Auth mutation strategy, real users or source rights. Prototype parsed-input UTF8 cap16MiB is not an HTTP streaming cap. Existing eight-table snapshot exclusions remain. Gateway credentials can still impersonate the owner through delegated parameters: production needs separate trusted server isolation/credential routing; this closure is not a defense against credential theft or compromised verifier/query code.

Verification: RED placeholder positive failures; unit identity/snapshot/isolation/error tests; actual disposable PGlite fixture stage/retry/denial/corrupt-readback/lost-delivery tests with gateway SQL role; existing native login/race/WAL regressions retained in CI. No new dependencies or provider service.

Trusted query contract: use one autocommit transaction per statement, resolve only after commit acknowledgement, and never inject a client in an open caller-managed transaction. The generic query callback cannot prove this by itself; actual connector/pool/rollback/lost-ack behavior is a hosted acceptance gate. Current integration verifies real autocommit PGlite behavior.
