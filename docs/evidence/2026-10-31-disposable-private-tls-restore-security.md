# Restricted private TLS connector and real restore-negative controls — 31 October 2026

**Result: DISPOSABLE NATIVE PostgreSQL 17.6 and 18.6 TLS/SCRAM plus genuine pg_dump/pg_restore PASS. Production readiness NOT established.**

The previous [private connector trust design](2026-10-31-private-connector-trust-boundary.md) required authentic encryption/hostname verification, role attestation, restricted grants and a way to reject obsolete authorization restored from backup. The first native attempt failed **only** during backup preparation because the minimal embedded server distribution lacked `pg_dump`; TLS and negative login controls had already passed. The final harness installs the **official PostgreSQL 18 client utilities** from the PostgreSQL apt repository on ephemeral GitHub CI runners (not project hosting or learner devices) and dumps/restores real disposable private-schema data for both PostgreSQL majors.

**Successful integration evidence:** [GitHub Actions run #41214779035](https://github.com/mdmoazzam291/Medical_Learning_OS/actions/runs/41214779035), both `evidence-native-postgres17` and `evidence-native-postgres` jobs PASS. Each log includes:

## Implementation and observations

1. **Disposable TLS-only PostgreSQL:** `startDisposableNativePostgres({postgres,tls:true})` generates a one-day testing CA and server certificate for localhost/127.0.0.1, secures the private server key, and installs a local TCP `hostssl`/SCRAM-SHA-256 `pg_hba.conf` with `hostnossl ... reject`. The private server listens **only on 127.0.0.1**; the Unix socket is retained only for disposable superuser fixture setup. All temporary files/credentials are destroyed on exit. Existing non-TLS test clusters preserve their previous socket-only behavior.
2. **Strict private connector:** `createIsolatedPrivateTlsQuery` requires the precise loopback hostname, port 55432, approved isolated database name, explicit confirmation, strong disposable password, trusted CA and login `evidence_private_gateway`. The caller cannot supply arbitrary SQL: only fixed `stage` and `reserve_intent` calls with exactly four validated bindings are allowed. Before executing either it verifies the Node TLS socket is encrypted and authorized, PostgreSQL `pg_stat_ssl` reports SSL, and `session_user`/`current_user` both equal the direct-login gateway, with `rolsuper=false`, `rolbypassrls=false`, `rolcanlogin=true`. Unknown conditions fail closed and connection closes.
3. **Real negative probes:** plaintext, wrong password, wrong certificate authority, bad TLS server hostname, improper credential identity, role substitution, arbitrary SQL, direct table access, forbidden controller/ack RPCs and `SET ROLE` are rejected. Separate unit tests reject malformed input before allocating any DB client and check network cleanup after failures.
4. **Authentic backup/restore:** `pg_dump -Fc` archives only the MLOS-owned `evidence_private` schema, then `pg_restore` recreates it in a **second disposable database**. An audit verifies the non-login owner, restricted login, table SELECT denial, exact function execute grants, four designated `SECURITY DEFINER` functions and locked `search_path` settings. Temporary controller/recording roles remain local and independent from provider Auth.
5. **Restore quarantine and invalidate:** the test revokes PUBLIC database CONNECT before restoring. The gateway cannot enter the restored database. The dumped state can contain a **still-enabled but stale lease**. The privileged restore procedure explicitly increments each restored subject epoch, sets `enabled=false` and expires leases before granting database CONNECT to the gateway. The restored gateway is then denied authorization. Testing GRANT SELECT on the private receipts table and GRANT EXECUTE on the controller function causes the manifest audit to reject, until grants are removed.

## Important limits

- **Not a hosted secret/TLS implementation:** test certificates and SCRAM passwords are ephemeral. No credential rotation, multi-host failover, hosted Postgres TLS chain, private Worker transport, production firewall, key vault or permissioned runtime release was implemented. In particular, the real test's gateway URL is **restricted to localhost** and cannot accidentally be pointed at a hosted project.
- **Restore procedure is not yet atomic with external publishing:** the test revokes general CONNECT *immediately after creating* its dedicated restored database, before restoring the schema. Production needs a stronger isolated restore/offline deployment lifecycle that makes it impossible for any gateway to connect **before** privileges and epochs have been audited and frozen; the test does not establish that for a live service.
- **Not a delivery transport proof:** `stage` and `reserve_intent` only authorize a private bookkeeping operation. No actual external delivery or signed provider acknowledgement took place. The separate private delivery intent/reconciliation prototype remains the source of the at-most-one-intent guarantee and the ambiguity policy.
- **Provider revocation remains non-atomic:** a provider verification result cannot be locked into one transaction with this MLOS-owned SQL state. User/session revocation detection, MFA, password changes and expiry remain independent acceptance blockers. This test did **not** modify or read hosted `auth.users`/`auth.sessions` rows or permissions.
- **Release controls:** PR #346 DRAFT/unmerged; evidence gateway default OFF. Source rights, clinical accuracy, institutional scope, learner privacy and medical publication all remain unapproved by this security test.

**Next useful acceptance:** design and test an authenticated **outbound acknowledgement source** with an independent durable correlation and an ambiguous-commit restart replay, without publishing clinical content. In parallel, provider-revocation semantics and a deployable isolated credential lifecycle still require separate evidence.
