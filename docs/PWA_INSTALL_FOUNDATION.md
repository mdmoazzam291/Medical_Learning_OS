# PWA install and launch foundation

This implements the first slice of the owner-approved21October website/PWA roadmap on a separate feature branch from main91a11aff. It does not depend on the separate learner-identity staging gate and does not merge or deploy this branch.

The same-origin `/web/manifest.webmanifest` gives Medretica stable app id `/`, launch `/`, scope `/` and standalone display. Root launch uses existing signed-in/signed-out routing; it does not persist an account, token, current Admin URL or return query in install metadata. Orientation is unconstrained so existing responsive portrait/landscape behavior remains available. All21servedHTMLentries statically link the same manifest before application scripts. Existing180Apple artwork is retained, with Apple standalone/defaultstatusbar metadata.192/512PNGicons use the exact approved favicon SVG geometry in its static light Sage/white colors, purposeany; no maskable suitability is claimed.

The three static assets are explicitly allowlisted. Node serves application/manifest+json; the static bundle has an exact manifest MIME header and retains no-store/CSP/security headers. No serviceworker, offline/private-content cache, queue/sync, forced update, install prompt, analytics, auth or application dependency is introduced. Icons were rasterized from the existing vector using isolatedresvg2.6.2; original vector/Apple assets remain unchanged.

Tests cover stable identity/launch/privacy, decoded PNG dimensions, metadata in each served head, exact packaged assets, static MIME and actual local HTTP allowlist/manifest/icon responses. Existing brand browser checks exercise built-bundle manifest/Apple discovery and image decoding at390/820/1440px, Chromium manifest parsing and no serviceworker registration. WebKit checks discovery and assets; it cannot establish actual iOS home-screen installation. Existing palette/appearance tests remain intact. The sign-in preservation test retains its original hashes and permits only the exact new head-metadata suffix; every other byte stays frozen.

Real-device acceptance remains pending: deploy an approved candidate over HTTPS, use Safari Share→Add to Home Screen on iPhone/iPad and supported Android/desktop install actions, inspect icon/name/standalone/rootlaunch, sign in and reopen, test links/back navigation and both orientations. Confirm supported persistence and absence of unexpected browser-only loops on each OS. Install UX and OS storage/session behavior vary; do not promise offline study, identical browser support or persistent sessions from metadata alone. No production release, clinical/reviewer/rights approval or learner onboarding gate is cleared.

References checked2November2026: https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Guides/Making_PWAs_installable and https://developer.mozilla.org/en-US/docs/Web/Progressive_web_apps/Manifest/Reference.
