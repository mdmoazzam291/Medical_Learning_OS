This implements the first slice of the owner-approved21October website/PWA roadmap on a separate feature branch from main91a11aff. It does not depend on the separate learner-identity staging gate. No production merge or deployment is performed; the existing pipeline publishes feature previews.

The same-origin `/web/manifest.webmanifest` gives Medretica stable app id `/`, launch `/`, scope `/` and standalone display. Root launch uses existing signed-in/signed-out routing; it does not persist an account, token, current Admin URL or return query in install metadata. Orientation is unconstrained so existing responsive portrait/landscape behavior remains available. All21servedHTMLentries statically link the same manifest before application scripts. The three static assets are explicitly allowlisted. Node serves application/manifest+json; the static bundle has an exact manifest MIME header and retains no-store/CSP/security headers. No serviceworker, offline/private-content cache, queue/sync, forced update, install prompt, analytics, auth or application dependency is introduced. Icons were rasterized from the existing vector using isolatedresvg2.6.2; original vector/Apple assets remain unchanged.

Tests cover stable identity/launch/privacy, decoded PNG dimensions, metadata in each served head, exact packaged assets, static MIME and actual local HTTP allowlist/manifest/icon responses. Real-device acceptance remains pending: deploy an approved candidate over HTTPS, use Safari Share→Add to Home Screen on iPhone/iPad and supported Android/desktop install actions, inspect icon/name/standalone/rootlaunch, sign in and reopen, test links/back navigation and both orientations.
